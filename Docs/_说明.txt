这个文件夹是什么？
==================

这是 RimForex 模组的**开发文档与验证脚本**。

RimWorld 不会读取这个文件夹
---------------------------
游戏加载模组时只认这几个目录：

    About/  Assemblies/  Defs/  Patches/  Languages/  Textures/

`Docs/` 不在其中，所以它**不影响游戏运行**。
留在这里是因为这些脚本是交付前的门禁，随手可跑。

脚本都是离线的
--------------
不依赖游戏、不需要启动 RimWorld，直接用 Python 跑：

    python Docs/audit.py
    python Docs/verify_spread.py
    python Docs/verify_texture.py
    python Docs/deadcode.py
    python Docs/pacing_analysis.py

各脚本做什么
------------
  audit.py            主门禁。翻译键一致性、XML 合法性、DefInjected 路径、
                      关键常量与不变量、各类回归防线（约 40 条检查）。
                      必须「全部通过」。

  verify_spread.py    经济验收。点差 / churn / 杠杆上限 / 盈亏方向等 9 项。
                      改行情模型或费用后必须全过 —— 它守的是"这个经济系统
                      还成不成立"，而不是某个具体数值。

  verify_texture.py   纹理度验收。离线复刻新旧两套行情模型做对比，
                      量化"K 线像不像行情"（纹理度 / 段间离散 / 影线实体比）。
                      补的是 verify_spread 的缺口 —— 后者只验经济性质，
                      纹理再差也照样通过。

  deadcode.py         死代码扫描。四层：翻译键 / 未使用文件 / 成员引用 /
                      Scribe 字段考古。**只报告，不修改** —— 判定需要人工复核。

  pacing_analysis.py  报价节奏 vs 摩擦的权衡分析。

  短线抑制方案-外部报告与核对.md
                      外部 agent 写的短线套利抑制方案，含核对记录。

文档
----
  开发笔记.md          面向**维护者**的技术文档（玩家看仓库根目录的 README）：
                      编译与发布、数值设计推导、实现要点、验证门禁、
                      历史踩坑与死代码记录、目录结构、缺口清单。

                      **刚接手、或者上下文被压缩过时，先读它的 §0 速查表**
                      —— 关键常量、不可破坏的规则、当前版本状态都在那一节。

交付前跑什么
------------
    python Docs/audit.py           必须「全部通过」
    python Docs/verify_spread.py   必须 0 失败
    python Docs/verify_texture.py  必须 0 失败
    python Docs/deadcode.py        只报告，[DEAD?] 需人工判断

验证边界（重要）
----------------
这些脚本覆盖的是**编译期 + API 级 + 数值**三层。

**它们不包括视觉与手感。** 窗口布局、文字遮挡、颜色、玩法是否有趣 ——
这些只能靠实际游玩。

而且历史证明：**真实游玩发现的 bug 最多**。读档崩价、强平漏收费、
图表文字打架、结算口径错误，全都是玩出来、或者从导出的真实交易记录里
逐笔核对才发现的。脚本一条都没抓到。

所以：脚本全过 ≠ 可以发布。两者都需要。
